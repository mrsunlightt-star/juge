# 句阁 · 支付接入总结与持牌机构/聚合SaaS清单

> 背景：个体户（有营业执照）销售自营 App（句阁）会员激活码（数字内容），拟在 App 内 + 官网（puretxt.cn，已 ICP 备案）收款。
> 更新日期：2026-09-15

---

## 第一部分 · 重要概念总结

### 1. 关系到"收款通道"的核心概念
- **持牌第三方支付机构（PSP/支付牌照）**：经人民银行颁发《支付业务许可证》的机构（拉卡拉、杉德、通联、汇付、易宝、快钱、银盛、宝付、富友、国通星驿等）。只有它们能做合规清算。
- **直连商户 vs 间连/特约商户**：
  - 直连：你直接向微信/支付宝商户平台各自申请商户号（要分别过它们的类目审核）。
  - 间连（特约/聚合收单）：你只向一家持牌机构（如拉卡拉/杉德）进件，它作为"服务商/收单机构"替你向微信、支付宝报备**子商户**。**只需开一个商户号**，无需再自己开微信+支付宝两个号。
- **收单（Acquiring）/ 结算（Settlement）**：收单=替你承接交易；结算（T+1 或 T+0）=清分后把钱打到你法人储备卡/对公账户。你看到资金进"拉卡拉商户"≠钱停在它那里，而是"清算经它，最终回你账户"。

### 2. 关键流程概念
- **进件（商户入网）**：把主体资料提交给收单机构审核 → 建档 → 分配商户号（MID）。可理解为"收款账户的开户审批"。
- **类目 / MCC**：给交易申报的经营类别。你类目必须报 **"软件 / 数字内容 / 自营应用授权"**，**严禁报"卡密/激活码/充值"**（后者被判预付卡/卡券类，易被拒或需备案）。钱包/机构对虚拟商品类目偏严，需以审核为准。
- **通道产品**：聚合扫码（微信/支付宝/云闪付）、App 收银台、H5、网关支付、快捷支付（绑卡）、银联云闪付/网银（走银行卡，不依赖微信支付宝钱包）。

### 3. 为什么 App 内支付也要有"后端"（重要）
- **App 收不到支付成功回调**。支付结果通知必须发到一个**可被互联网访问的服务器地址**上。所以哪怕全部自研，也必须有轻量后端来"收到已支付回调 → 验签 → 下发激活码 → 记录订单"。
- 发卡系统（独角数卡）= 现成的"订单+库存+自动发货+对账"后端；自研 = 更贴 App 内收银、更可控。

### 4. 安全硬指标（对接时必须做）
- **回调验签**：用商户密钥校验签名，拒绝未通过校验的请求。
- **订单幂等/去重**：同一 outTradeNo 重复回调只发一次码。
- **防重发码**：发码在验签成功且标记"已发货"后再执行。
- **掉单兜底**：回调丢失时按订单号主动查询补发。
- **金额校验**：以回调/查询实付金额为准，不盲信前端金额。

### 5. 费用相关概念
- **手续费/费率**（真正的核心成本，按交易额）：扫码约 0.38%；贷记卡 0.55~0.60%；借记卡 0.5~0.6%（单笔封顶约 20 元）。App/官网扫码场景大概率落在 0.38%~0.6%。
- **一次性费用**：正规在线收单进件/开户一般 0 元，无设备。
- **结算**：T+1 一般免费；T+0（秒到）部分机构/服务商另收秒到费。
- **只针对线下 POS 机的费用**：设备押金（99/199/299 元）、流量费（次年起 48~60 元/年）——你走在线收单**不适用**，别被当成"固定成本"。
- **雷区**：超低费率=套码/跳码违规；"开通费/押金/保证金"正规收单罕见；无法出示持牌授权=二清灰色；费率与类目不一致。

### 6. "聚合支付"的层级与混淆点
- **下层（清算者）**：持牌机构（拉卡拉/杉德等）真正清分。
- **上层（产品/应用层）**：聚合支付 SaaS（有赞、汇付斗拱、通联收付通等）把多个持牌通道包起来，对外统一 API/后台、做分账/对账。**它是可选的增值层，未必必须**——你现在的体量直接接官方开放平台即可，不必多叠一层（那会多收服务费）。
- **警惕**：无牌照、嵌套三四方的"聚合平台"=二清，坚决不用。只选有持牌机构背书的。
- **"不用支付宝/微信"的现实**：国内线上收单几乎无法 100% 脱离这两个钱包（银联/云闪付可与银行卡并列，但云闪付生态也连通）。"清算机构换成持牌机构、资金直达自己账户"才是可行诉求。

### 7. 跨境方向（季季）为何不适合
- 连连全球支付面向 PSP/出海电商平台，需企业主体 + KYC，做多币种收单与分发，个人/小 App 卖会员用不上，费率与复杂度都不划算。

## 第三部分 · 持牌机构背书的聚合支付 SaaS / 服务商

> 这些是"上层产品层"，底层可落到持牌机构清分。**按需选用**：你直接接官方开放平台即可起步，除非需要多通道统一后台/分账，才用聚合 SaaS。

| 聚合支付 SaaS / 平台 | 说明 |
|---|---|
| **有赞支付** | 聚合微信、支付宝、银行卡等，称持央行牌照 [官网](https://www.youzan.com/payment)；适合有店铺/电商场景 |
| **拉卡拉开放平台** | 面向 H5/PC/App/小程序，适合自建官网/App 直接接入 [open.lakala.com](https://o.lakala.com/open/home/index) |
| **通联收付通 / 收银宝** | 通联体系，适合有开发能力或已有通联服务商支持的企业/个体户 [文档](https://prodoc.allinpay.com/doc/548/) |
| **汇付斗拱** | 聚合支付类 API，适合服务商/ISV 或自有开发团队 [斗拱API](https://paas.huifu.com/open/doc/api/) |

**核验持牌背书的通用方法**（防二清）：
1. 要求出示**持牌机构官方授权/合作协议**，或到该持牌机构官网核实其"授权服务商"名单。
2. 拒绝任何"需预存押金、先交保证金、超低费率"的双向免费/脱离合同报价。
3. 交叉验证费率与类目是否一致（类目/MCC 与营业执照经营范围、实际场景相符）[$TRAE_REF](https://pcs.unionpay.com/files/cms_files/filemanager/1708704992/attach/20239/%E6%97%A0%E5%8D%A1%E8%87%AA%E5%8A%A9%E6%B6%88%E8%B4%B9%E4%B8%9A%E5%8A%A1%E5%95%86%E6%88%B7%E5%85%A5%E7%BD%91%E8%AF%84%E4%BC%B0%E8%A6%81%E7%82%B9%E5%8F%8A%E6%B5%81%E7%A8%8B%EF%BC%88%E9%80%9A%E7%94%A8%E7%89%88%EF%BC%89%EF%BC%88%E8%AF%95%E8%A1%8C%EF%BC%89-2023%E5%B9%B49%E6%9C%88.pdf)。
4. "同时经营实物+虚拟商品"时，微信侧可能需分别申请商户号（参考[微信支付商户说明](https://pay.weixin.qq.com/static/protocol/protocol_v2.shtml)）。

## 建议下注（简单结论）
- **首选**：拉卡拉 / 汇付（斗拱）——个体户支持明确、有开放 API、对私结算可确认，且与你的 App/官网收银台场景匹配。
- **备选**：通联、快钱、银盛、宝付、国通星驿——确认个体户与对私结算后再选。
- **杉德、随行付**：开放平台存在，但个体户主体需专门确认。
- **原则**：要么官方开放平台直连，要么有明文持牌背书的聚合 SaaS；任何无法出示持牌授权、要押金、承诺超低费率的，一律按二清风险剔除。
