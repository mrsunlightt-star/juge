## 一、总体结论

项目整体工程质量**高于个人开发者平均水平**：支付链路核心（验签→金额核对→幂等落单→服务端查单确认）实现规范，隐私政策文本与代码实际行为一致，密钥未入库，权限最小化。

**但存在 1 个必须立即修复的 P0 问题**：Release 包中带有一个无任何门控的"开发者一键激活 PRO"开关，所有用户可见可用，等于付费墙形同虚设。另有 8 个 P1 问题建议在上架前修复/核查。

## 二、P0 — 阻断上线（必须修复）

### P0-1 开发者后门开关未移除，任何用户可一键免费激活 PRO

**证据**：`app/src/main/java/com/juge/app/MainActivity.kt:1052-1068`（调用）、`597-625`（定义）

代码注释自己写着"发布前必须整块删除——留着等于把付费墙拆了"，但 `DevProToggle` 这个 Switch **没有任何 BuildConfig.DEBUG 判断**，直接渲染在主界面，Release 包中所有用户点一下即永久激活 PRO。且 `app/build.gradle.kts:50-52` 未开启 `buildConfig = true`，即使想加门控当前也不可用。

**修复**：删除 `DevProToggle` 函数及全部调用点；如需保留调试能力，先开 `buildConfig = true` 再用 `if (BuildConfig.DEBUG)` 包裹。

### P0-2（关联风险）激活状态纯本地判定，算法与盐全在 APK 内

**证据**：`app/src/main/java/com/juge/app/data/TrialManager.kt:143-170`

XOR 混淆 + SHA-256 校验和的全部算法、盐（`"TrialManager_v2_2026"`）、原始键名都在 APK 内。root 用户可离线算出键值直接写 SharedPreferences 破解；Xposed/Frida hook `isActivated()` 更是一步到位。

**客观评价**：对 1.99 元买断产品，这是可接受的防盗水位（防君子不防高手），但有两个具体缺陷值得修：
- 已登录用户冷启动时只在"服务端说 PRO"时单向写入本地，`serverSaysPro = false` 时不清除本地激活（MainActivity.kt:656），盗号/共享账号场景下本地激活永久残留；
- `activate()` 是公开方法、无服务端凭证入参。

**修复 P0-1 后本项可降级为 P2**，但建议做 (a) 冷启动用服务端状态覆盖本地（双向），(b) `ServerClient.baseUrl` 改 `val`（见 P1-4）。

## 三、P1 — 上架前应修复/核查

### P1-1 服务端金额缺失时跳过核对直接置为已支付

**证据**：`lkl-pay-server/src/main/kotlin/com/juge/lklpay/service/PayOrderService.kt:71-78`

`yuanToFen()` 解析失败返回 null 时，整个金额核对被跳过，订单照样置 PAID 并开通 PRO——与类注释"金额不符一律拒绝"自相矛盾。实际可利用性低（验签通过的报文必带金额），但这是防改价的最后一道闸，不应留"跳过"分支。
**修复**：`paidFen == null` 同样拒绝置 PAID，ERROR 留档。

### P1-2 下单/查单接口无频率限制，可被刷单

**证据**：`AlipayController.kt:53-84`（create）、`95-118`（query）

`/api/alipay/create` 对任何人开放且无节流，每次调用写一行 DB，攻击者可刷爆 H2 库与日志；`/api/alipay/query` 对游客订单直接转发支付宝网关，可放大消耗 QPS 配额。`LoginThrottle` 只保护了 `/api/auth/*`。
**修复**：复用 LoginThrottle 的 IP 维度计数，create/query 加限流（如 20 次/分钟）。

### P1-3 运维核查：8081 明文 HTTP + 无条件信任 X-Forwarded-For

**证据**：`application.yml:17-18`（8081 无 TLS）；`AuthController.kt:120-129`（无条件信任 XFF 头）

TLS 完全依赖 Nginx，仓库内无 Nginx 配置可审。**上线前必须确认两件事**：
1. 腾讯云安全组仅放行 80/443，8081 仅本机回环可达（否则 Bearer token 可明文直达 8081）；
2. Nginx 覆写 `X-Forwarded-For`（`proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;`），否则攻击者自带 XFF 头即可绕过 IP 维度登录节流。

### P1-4 App 端：图片裁剪在主线程解码/压缩，ANR 风险

**证据**：`app/src/main/java/com/juge/app/CropImageHelper.kt:231-239`（主线程 decode 2048² 位图）、`352-362`（保存按钮主线程压缩 4096² PNG 写盘）

**修复**：解码与保存均挪 `Dispatchers.IO`，保存加置忙态。

### P1-5 ProGuard 规则包名写错，keep 规则全部失效

**证据**：`app/proguard-rules.pro:2-3` 写的是 `com.example.myapplication.data.*`（模板工程残留），实际包名是 `com.juge.app.data`。

当前侥幸无影响（WidgetStyle 全是代码直接引用），但规则失效意味着今后加反射/序列化场景无保护。同时建议 release 块加 `isShrinkResources = true`（当前 26 张 webp + 6 个字体未做资源裁剪）。
**已核查无需手动补的规则**：支付宝 SDK 与 Coil 均自带 consumer ProGuard rules，会自动合并。

### P1-6 App 端：服务端地址是可变 var，无证书固定

**证据**：`app/src/main/java/com/juge/app/net/ServerClient.kt:17`（`var baseUrl`）

被 hook 后支付/登录流量可被整体重定向到攻击者服务器。系统默认 HttpURLConnection 无证书固定，设备被植入 CA 时 Bearer token 可被中间人截获。
**修复**：`baseUrl` 改 `val`（联调用 BuildConfig 字段区分环境）；对 puretxt.cn 加证书 pinning。

### P1-7 合规：官网无隐私政策页面、首页无备案号展示

**证据**：`juge-website/` 全目录仅 index.html 一个页面，grep 确认无"隐私政策/用户协议/备案"任何字样。

两个后果：
1. **上架硬门槛**：华为/小米/OPPO/vivo 提交时均要求填写"隐私政策 URL"，当前没有可填的页面；
2. **备案合规**：已备案网站须在首页底部展示备案号并链接至 beian.miit.gov.cn，长期不展示有被注销备案风险（且 App 内已展示 赣ICP备2026021624号-2A，网站端 -1 号也应展示）。

**修复**：官网增加 /privacy.html 与 /agreement.html（可直接复用 LegalDocs.kt 全文），首页底部加备案号链接。

### P1-8 合规：账号注销仅"发邮箱人工处理"，存在被商店驳回风险

**证据**：`LegalDocs.kt:131,147`；代码中无任何 App 内注销入口。

华为、小米等市场近年审核要求"App 内提供便捷的账号注销方式"，纯邮箱人工处理有被驳回先例（尤其账号体系含付费权益）。
**修复（二选一）**：(a) App 内加"注销账号"入口（登录后调服务端删除接口，服务端需新增该接口）；(b) 至少把注销入口做进账号面板，写明处理时限（如"15 个工作日内"）。方案 (a) 更稳妥。

## 五、已验证无问题的项（可放心）

- **支付核心链路**：回调验签（rsaCheckV1 + RSA2 + app_id 二次校验，AlipayPayService.kt:131-146）；客户端不以 SDK 返回的 9000 直接激活，而是轮询服务端查单确认 TRADE_SUCCESS（ProPurchase.kt:120-131）；下单不传金额、金额取服务端目录（防 1 分钱改价）；订单号时间戳+48bit 随机、令牌 256bit SecureRandom 且只存 SHA-256 摘要；口令 PBKDF2 210k 迭代 + 恒定时间比较 + 不存在账号陪跑哈希；登录双维度节流。
- **密钥管理**：keystore 密码、支付宝私钥、商户信息均未入库（.gitignore 完备，git 历史核查无踪迹）；APK 内无硬编码密钥（加签全在服务端，符合规范）。
- **权限合规**：仅声明 INTERNET，无冗余权限；相册通过系统选择器读取，符合工信部"最小必要"要求；支付宝包可见性 `<queries>` 声明正确。
- **隐私合规（App 内）**：首次启动弹窗含"同意/不同意并退出"双按钮、协议全文可应用内查阅；App 备案号（赣ICP备2026021624号-2A）已展示并可跳转工信部查询页；隐私政策文本与代码实际行为逐条核对一致（含备份排除策略的真实描述）；无广告/统计 SDK。
- **数据存储**：数据库全参数化查询无注入面；激活状态、Token、隐私同意、组件绑定均已在备份规则中排除。
- **Widget 稳定性**：goAsync + 8 秒超时兜底、单线程渲染队列、位图采样加载、模糊前压尺寸，主线程纪律良好。
- **字体版权**：6 款内置字体均为 OFL/IPA 开源授权，全文声明已内置应用内，子集化裁剪方式已在文档中如实说明。
