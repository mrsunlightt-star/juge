# 上线前结构性重构记录：2026-10-05

本文记录「上线前结构性重构」的范围与验证结论（计划与 issue 清单在 `.scratch/prelaunch-refactor/`，
该目录不入库）。动机是上线后没有精力维护：与其带着巨型文件缝缝补补，不如在无用户、
无线上压力、可随时回滚的阶段把结构先做对。仓库尚未上架。

重构针对两处**成本随功能线性增长且已经固定**的结构问题：

1. `WidgetCanvasRenderer`：3616 行、主 `render()` 单函数 718 行，形状差异靠 47 处散落的
   `style.shape == X` 表达；
2. `MainActivity`（3424 行）/ `QuickAdjustActivity`（1366 行）里的巨型 composable。

## 硬约束与安全网

**行为不变**：像素级渲染结果、数据库结构、UI 视觉与交互均不得变化。
判据不是「看起来一样」而是位级指纹——`WidgetRenderBaselineTest` 对全部风格 × 尺寸记录指纹，
重构前后逐条比对，任何一条不一致都必须解释清楚。

- 渲染基线：`app/src/test/resources/widget-render-baseline.tsv`，51 个风格 × (4×2 / 4×4)
  + 4×2 长文本 = **153 条**，每条比对整图像素哈希、不透明占比与 8×4 网格平均色。
- UI 基线：拆 `MainActivity` 前先建 Robolectric 截图/结构基线，见下面第二节。

## 一、拆 `WidgetCanvasRenderer`（issue 02）

### 1/2 纯搬移（提交 `772c957`）

按「种子 + 引用闭包」把家族辅助函数移入 `render/` 下的 `internal object`，
跨家族真正共享的 10 个原语留在 `WidgetRenderKernel`：
City / Sticker / Bookshelf / WeatherBox / Subor / Paper / Soil / Feather / TornPaper /
SplitCard / Tape / BlueNote 共 13 个家族文件。搬移只改可见性与 import，
调用点写法不变（成员由调用点 import）。

`WidgetCanvasRenderer` 3616 → 1341 行；验证：49 单测全绿、153 条指纹位级一致、
release 包字体 7 / 图片 66 / 21MB 不变。

### 2/2 收敛分派（本次）

把「形状」变成管线的一等公民：新增 `render/ShapeTraits.kt`，24 个形状在管线里的
全部差异（是否内缩 4dp / 是否强制直角 / 是否整幅透明底 / 是否走整卡铺图 / 圆角是否
跟随用户设置 / 填充是否跟随撕边）集中到一张表，`WidgetShape.family()` 用**穷举 when**
（不写 `else`）把形状映射到 13 个家族——新增风格时编译器会强制要一个归属。
原先同一条名单最多被抄了四五遍，漏改一处就是「A 风格正常、B 风格错位」。

管线按阶段拆开，`render()` 只做尺寸换算与阶段调度：

| 文件 | 职责 | 行数 |
| --- | --- | --- |
| `WidgetCanvasRenderer.kt` | 对外入口 + 阶段调度 + 缩略图缓存 | 1341 → **252** |
| `render/ShapeTraits.kt` | 形状家族与差异表（单一事实来源） | 新增 169 |
| `render/WidgetRenderPipeline.kt` | `RenderScene` 状态 + 底色/背景图/家族装饰/纹理描边/叠加层 | 新增 571 |
| `render/CardTextRenderer.kt` | 正文安全区（16 个排版分支的唯一入口）+ 正文绘制 | 新增 362 |
| `render/FramedCardRenderer.kt` | 画框卡片族（4 个风格共用一张比例表，`specFor`） | 新增 173 |
| `render/BgImageRenderer.kt` | 背景图铺法（拉伸/裁切/等比/平铺 + 模糊 + 蒙版） | 新增 125 |

`render()` 718 → **32 行**；最大单文件 571 行（上限 800）。
家族装饰由一串互斥的 `if (style.shape == X)` 变为 `when (family)`，
父级管线不再随风格数量增长。

**与「只搬移」清单的差异（两处，均已单独确认）**：

- 删除 `render()` 中一段 `canvas.save(); canvas.clipPath(path); canvas.restore()`
  ——保存后立即恢复的裁剪，对画布没有任何影响，属残留代码；
- 删除一个死变量（`render()` 里的 `val renderStyle = style`，从未被引用）。

两者都不改变绘制结果，且被下面的证据覆盖。

## 二、建 UI 基线（issue 03 的前置）

拆 `MainActivity` 需要和拆 Renderer 一样的安全网，只是对象从「组件渲染结果」换成「整个界面」：
Robolectric 在 JVM 上真实渲染 Compose，把「整屏截图 + 语义摘要」压成指纹与基线比对。

- 测试：`MainUiBaselineTest`（主界面）、`QuickAdjustUiBaselineTest`（快捷面板）；
  帮助类 `UiFingerprint`（指纹）/ `UiBaseline`（基线读写、比对、失败诊断）/ `UiSnapshot`（采集）。
- 场景：`main-library`（跃然纸上）、`main-adjust`（个性定制）、
  `main-adjust-tutorial`（教程展开）、`quick-adjust`（快捷面板）。
- 基线：`app/src/test/resources/ui-baseline/`（`main.tsv` + `main/*.digest.txt`、
  `quick-adjust.tsv` + `quick-adjust/*.digest.txt`）。
- 判据两条：**截图像素 sha256** 位级一致；**可见语义摘要 sha256** 一致。
  摘要只收录完全落在屏幕内、且带用户可见属性（文本 / 无障碍描述 / 角色 / 开关状态）的节点，
  并按位置排序。懒加载列表会把视口外的条目提前组合出来，数量每次运行都不同，
  不摘掉的话基线一直在抖。
- 两处 Robolectric 特有的坑，已在帮助类里注释说明：
  快捷面板是对话框式 Activity，面板画在 Compose Dialog 的窗口里（要截对话框的 content，
  不是 Activity 的）；`QuickAdjustActivity` 的 `setContent` 晚于窗口首次布局遍历，
  视图尺寸会停在 0（需按屏幕尺寸补一次测量/布局）。
- 异步内容：风格缩略图由 `produceState + Dispatchers.Default` 渲染，截到第一帧还是
  渲染完成后全看后台线程快慢（实测同一份代码会截出「有缩略图」和「空白」两种图）。
  采集时先等够 1s，再要求「连续 300ms 画面不变」，把这种抖动挡在基线之外。

验证（`--rerun-tasks` 强制真实重编重跑）：

1. 连续 4 次全量重跑，四个场景全部一致；
2. 阳性对照：`selectBlue` 由 `0xFF42B8EC` 改成 `0xFF42B8ED`（只差 1）→ 三个场景立刻失败；
   把「录入新句」按钮图标的 `contentDescription` 改成 `AddReminder`（像素不变）→
   摘要比对失败并打印出错行；
3. `./gradlew :app:testDebugUnitTest` 11 类 / 51 用例全绿。

## 三、验证证据（issue 04）

```bash
./gradlew :app:testDebugUnitTest      # 10 个测试类 / 49 用例，0 失败
./gradlew :app:assembleRelease        # 成功；APK 22,256,677 字节（与拆分前同）
```

1. **153 条渲染指纹位级一致**（`WidgetRenderBaselineTest`）。
2. **预设覆盖不到的路径单独验证**：唯一没有被任何预设使用的形状是 `ELLIPSE`。
   把重构前后两份实现分别编译（`--rerun-tasks` 强制真实重编重跑），对
   ELLIPSE（默认 / 圆角 30 / 描边+纸纹+双引号 / 半透明无阴影 / 渐变）+ 矩形描边 +
   撕裂纸 + 手账胶带 × 2 尺寸共 18 条指纹逐条比对，结果相同。
3. **阳性对照**：把 `CARD_INSET_DP` 由 4f 改为 5f 后基线测试立刻失败——
   证明基线与执行链路对这种量级的改动是敏感的（否则上面的「一致」没有意义）。
4. **绘制调用清点**：把重构前后 render() 管线里的画布绘制类调用做多重集比对，
   唯一差异就是被删掉的那一组 `save / clipPath / restore`。
5. **release 产物**：`assets/fonts` 7 项、`res/` 91 项（本次改动未触碰任何
   `res/` 与 `assets/` 文件），`mapping.txt` 含新类名
   （`CardTextRenderer` / `RenderScene` / `ShapeTraits` 等），证明产物确实由新代码构建。
6. 渲染结果位级不变，因此**缩略图磁盘缓存版本无需 +1**（缓存按「版本号 + presetId +
   尺寸」寻址，旧图与新代码产出的图完全相同）。
