# 句阁 · 聚合收单方案 A 落地清单（杉德/拉卡拉 + 自建独角数卡）

> 目标架构（一句话）：
> 用户用微信/支付宝在句阁官网（或 App 内）付款
> → 交易经**杉德/拉卡拉（持牌收单机构）**聚合收单
> → T+1 结算到**法人个人银行卡**
> → 自建**独角数卡**自动下发句阁激活码
> → 用户在 App 填入激活码 → 本地激活 PRO

- 更新日期：2026-09-14
- 前置条件：已有个体工商户营业执照；已有服务器可部署独角数卡；官网 puretxt.cn（已完成 ICP 备案）可作经营载体

---

## 阶段一：进件开通（个体户 → 间连特约商户）

### 1.1 准备材料（一次性备齐，避免反复被打回）
- 营业执照正本/副本彩色照片（清晰、无涂改、与法人实名一致）
- 法人（你本人）身份证正反面照片
- 法人本人储蓄卡（用于个体户结算，个体户一般可绑个人卡，无需对公账户）
- 经营/业务场景照片（门头照 + 收银台/经营场景，间连进件常要求）
- 作为"线上经营载体"的网站：puretxt.cn 首页需内容丰富、能正常访问、含完整商品与价格信息、ICP 备案在案

### 1.2 找对渠道（两种，二选一）
- **机构直签**：直接联系杉德/拉卡拉开户（官网/官方入口），流程正规但要求可能更严、沟通成本高。
- **服务商/代理商进件**（更常见）：找做"聚合收单 / 间连特约商户"认证的合规服务商进件，通常资料更省、下户更快。
  - 判断靠谱代理的硬指标：能出示**持牌机构官方授权/合作协议**；走机构正规进件系统；**不要求押金、不承诺"超低费率"**（0.38%～0.6% 是合理区间，明显低于此的往往是套码/二清陷阱）。

### 1.3 产品选型（跟服务商明确要什么）
- 产品：**聚合收单（微信 + 支付宝 + 云闪付扫码）**，开通在线/API 收单权限，用于官网小程序/网页/H5 收款。
- 结算：T+1 到法人个人卡（可谈 T+0，一般有加价）。
- 费率：扫码网关约 **0.38%~0.6%**；以签约合同为准，**把费率写进协议**。
- 接口：要**回调通知 + 签名验签**的标准 API；如走独角数卡，需确认该通道有对应接入方式（见阶段二）。

### 1.4 类目申报（决定能否过审，务必照抄）
- 申报经营类目用：**软件 / 数字内容 / 自营应用授权**。
- **严禁**报：卡密 / 激活码 / 充值卡 / 预付卡——会被判定为"卡券/预付"类目，倾向被拒或要求备案审批。
- 话术口径：句阁是**自营软件 Day/Day 会员授权**（卖自家 App 的 PRO 服务），属数字内容增值服务，类别完全站得住。

### 1.5 拿到的凭证
- 商户号（MID）、平台公钥 / 商户密钥、回调配置地址
- 沙箱/测试环境参数 + 生产环境参数
- 服务商客服/技术对接人联系方式（纳入后续对账与异常处理）

## 阶段二：技术对接（独角数卡 + 句阁激活码闭环）

### 2.1 部署独角数卡（复用已有服务器）
- 在现有轻量服务器（OpenCloudOS）上 Docker 部署独角数卡（dujiaoka）+ MySQL + Redis + 域名解析到收单回调可用域。
- 配置站点、商品、库存；上线前先 HTTPS。

### 2.2 绑定支付通道
- 独角数卡面板选择/安装应对应支付扩展；若机构和通道是杉德/拉卡拉聚合，需确认独角数卡有现成插件。
- **若无可直接用插件**：编写轻量对接层，把杉德/拉卡拉回调转成独角数卡的标准"已支付"回调（注意验签 + 幂等，见 2.4）。

### 2.3 句阁激活码闭环（与现有无后端模型保持一致）
- 生产激活码：在本地生成一批唯一激活码，人工录入独角数卡"卡密库存"。
- 用户付完单一独角数卡自动发货；用户在句阁 App 激活弹窗输入 → 触发现有 `TrialManager.activate()`（无需新增后端校验，延续当前本地激活模型）。
- 需要时再扩充：码与设备/订单绑定、码状态（未用/已用）、回收未支付订单。

### 2.4 对接硬性要求（安全全看这几条）
- **回调验签**：必须用商户密钥校验签名，拒绝未通过校验的请求。
- **幂等/去重**：同一 `outTradeNo` 重复回调只发一次码，防止重复发货。
- **防重发码**：发码动作放在回调验签成功后、且记录订单状态为"已发货"后再执行（码一旦发出不可撤回）。
- **掉单处理**：设置订单查询兜底（用户付款成功但回调丢失时，按订单号主动查询状态补发）。
- **金额校验**：以回调/查询返回的实付金额为准，不与前端下单金额盲信拼接。
- **日志**：保留完整请求、验签、发码日志，便于对账与异常排查。

## 阶段三：测试、上线、对账

### 3.1 测试
- 用测试环境走通：下单 → 付款 → 回调 → 发码 → 激活的完整链路。
- 实测异常：付款成功回调丢失（掉单补发）、重复回调、金额不符、用户中途取消。
- 移动端（手机扫码/微信内打开）与桌面端各测一遍。

### 3.2 上线
- 先小批量真实订单验证生产环境；通后再全量放开。
- 上线首周由你手动核对每一笔订单与发码记录。

### 3.3 长期对账与合规
- **对账**：按日核对 交易汇总 vs 结算到账 金额，发现差异走服务商工单。
- **退款**：明确退款流程与是否回收入口；已发码退款需人工回收库存。
- **税务**：个体户需就经营所得申报个税（按核定或查账征收），保留流水凭证；涉及"经营所得"记得按规申报，避免被稽查。

## 四、风险红黄线（做之前先过一遍）

| 风险 | 对策 |
|---|---|
| 类目被拒（因误报"激活码"类） | 一律按"软件/数字内容"申报，话术统一见阶段一 1.4 |
| 间连结算到账延迟/资金占用 | 接受 T+1，签约合同写清结算时效；不选"无资质、需要预存押金"的渠道 |
| 服务商跑路/二清 | 只选**持牌机构直签或持牌机构官方授权代理**；绝不接受个人"免签/转接"通道（非法二清） |
| 超低费率诱惑 | 0.38% 以下过低必存套码/跳码涉嫌，正规间连以合同为准 |
| 平台封绑 | 出问题优先走机构官方客服与工单，保留合同和进件证据 |

## 五、与"不用支付宝/微信"诉求的衔接
- 本方案用户端**照常用微信/支付宝**，但**收单/清分主体是杉德/拉卡拉**这类持牌机构，资金直接结算到你法人卡——即你要的是"清算机构不是微信/支付宝"，不牺牲用户支付体验。
- 将来若想完全绕开微信/支付宝生态（仅银联/银行卡），可在同一家机构加开"银联 JS/网银/快捷"通道作为补充入口，代码层面多一个支付按钮即可，架构无需大改。

1. 把阶段一 1.1 的材料整理成电子档。

5. 立项后按阶段二对接、阶段三测试上线。

## 七、给服务商/机构的费用核实表（进件前逐条问清，要求写进合同）

> 使用说明：对接杉德/拉卡拉（或其合规服务商）时，把下面每一条**当面/书面**问清楚并记录，能落合同就落合同。对方含糊其辞的项，就是要防的雷。

### 7.1 一次性费用
| # | 核实问题 | 期望的合规答案 | 约定的值/备注 |
|---|---|---|---|
| 1 | 进件/开户费多少？ | 正规收单一般 **0 元** | |
| 2 | 是否有开通费/押金/保证金/年费预存？ | 不应有大额前置费 | |
| 3 | 是否需要购买硬件或服务？（App 内收单不需要） | 不需要 POS/扫码设备 | |
| 4 | 技术服务费/SDK 授权费？ | 一般无 | |

### 7.2 手续费（核心，按交易额）
| # | 核实问题 | 参考区间 | 约定的值/备注 |
|---|---|---|---|
| 5 | 扫码（微信/支付宝/云闪付）费率？ | **约 0.38%** | |
| 6 | 贷记卡（信用卡）费率？ | 0.55%~0.60% | |
| 7 | 借记卡（储蓄卡）费率？ | 0.5%~0.6%，单笔封顶约 20 元 | |

### 7.5 雷区警示（对方出现以下话术，直接提高警惕）
- "超低费率"（明显低于扫码 0.38%）→ 多为套码/跳码，涉嫌违规、易被风控冻结。
- "先交押金/保证金才给开通" → 正规收单罕见。
- 不能出示**持牌机构官方授权/合作协议** → 很可能是二清灰色通道，坚决不用。
- "手续费全按信用卡收"但实际按扫码报备 → 类目与费率不一致。
- "后期会涨价无合同约束" → 费率必须写进合同并约定调价规则。
